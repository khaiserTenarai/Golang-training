# Employee Management API — Request URLs for Testing

**Base URL:** `http://localhost:8080`

## 1. Health Check and Middleware

### GET — 1. Health Check

**URL:** `http://localhost:8080/healthz`

**Expected Response:**
```json
{
  "status": "ok"
}
```

### GET — 2. Custom Middleware and Execution Order

**URL:** `http://localhost:8080/demo/middleware`

**Expected Response:**
```json
{
  "message": "middleware executed",
  "requestID": "generated-request-id"
}
```

The request ID is generated by the Request ID middleware.

### GET — 3. Abort Middleware

**URL:** `http://localhost:8080/demo/abort`

**Expected Status:** `403 Forbidden`

**Expected Response:**
```json
{
  "error": "request stopped by Abort middleware"
}
```

## 2. Login and JWT Authentication

### POST — 4. Login

**URL:** `http://localhost:8080/login`

**Request Body:**
```json
{
  "username": "admin",
  "password": "admin123"
}
```

**Expected Response:**
```json
{
  "message": "login successful",
  "token": "YOUR_JWT_TOKEN"
}
```

Copy the returned token and use it in the Authorization header for protected endpoints.

### GET — 5. Access Employees Without a Token

**URL:** `http://localhost:8080/employees`

**Expected Status:** `401 Unauthorized`

An authentication error is returned because the request does not contain a valid JWT.

### GET — 6. Access Employees With a Valid Token

**URL:** `http://localhost:8080/employees`

**Request Header:**
```text
Authorization: Bearer YOUR_JWT_TOKEN
```

**Expected Result:** A successful response containing employee data.

## 3. Employee CRUD Operations

The following requests require a working PostgreSQL database and an existing `employees` table.

### GET — 7. Get All Employees

**URL:** `http://localhost:8080/employees`

**Request Header:**
```text
Authorization: Bearer YOUR_JWT_TOKEN
```

**Expected Response if No Records Exist:**
```json
{
  "data": [],
  "page": 1,
  "page_size": 10,
  "total": 0,
  "total_pages": 0
}
```

### GET — 8. Pagination

**URL:** `http://localhost:8080/employees?page=1&page_size=5`

**Request Header:**
```text
Authorization: Bearer YOUR_JWT_TOKEN
```

**Expected Result:** Up to five employee records from the first page.

### GET — 9. Filter by Department

**URL:** `http://localhost:8080/employees?department=IT`

**Request Header:**
```text
Authorization: Bearer YOUR_JWT_TOKEN
```

**Expected Result:** Employees belonging to the IT department.

### GET — 10. Filter and Sort Employees

**URL:** `http://localhost:8080/employees?department=IT&name=Ravi&sort=name&sort_order=asc`

**Request Header:**
```text
Authorization: Bearer YOUR_JWT_TOKEN
```

**Expected Result:** Employees matching the department and name filters, sorted by name in ascending order.

Supported sort fields: `id`, `name`, `department`, and `salary`.

Supported sort orders: `asc` and `desc`.

### GET — 11. Get Employee by ID

**URL:** `http://localhost:8080/employees/1`

**Request Header:**
```text
Authorization: Bearer YOUR_JWT_TOKEN
```

**Expected Response if Employee 1 Exists:**
```json
{
  "id": 1,
  "name": "Ravi",
  "email": "ravi@example.com",
  "department": "IT",
  "salary": 35000
}
```

If the employee does not exist, the API returns `404 Not Found`.

### POST — 12. Create an Employee

**URL:** `http://localhost:8080/employees`

**Request Headers:**
```text
Authorization: Bearer YOUR_ADMIN_JWT_TOKEN
Content-Type: application/json
```

**Request Body:**
```json
{
  "name": "Ravi",
  "email": "ravi@example.com",
  "department": "IT",
  "salary": 35000
}
```

**Expected Status:** `201 Created`

The response contains the newly created employee and its generated ID.

### PUT — 13. Update an Employee

**URL:** `http://localhost:8080/employees/1`

**Request Headers:**
```text
Authorization: Bearer YOUR_ADMIN_JWT_TOKEN
Content-Type: application/json
```

**Request Body:**
```json
{
  "name": "Ravi Kumar",
  "email": "ravi@example.com",
  "department": "IT",
  "salary": 40000
}
```

**Expected Status:** `200 OK`

The employee is updated if the ID exists and the submitted data is valid.

### DELETE — 14. Delete an Employee

**URL:** `http://localhost:8080/employees/1`

**Request Header:**
```text
Authorization: Bearer YOUR_ADMIN_JWT_TOKEN
```

**Expected Status:** `204 No Content`

A repeated delete may return `404 Not Found`.

## 4. File Upload

### POST — 15. Upload a File

**URL:** `http://localhost:8080/upload`

**Status:** Not implemented in the current controller.

The `/upload` endpoint must be added to the project before this request can succeed. Until then, it will return `404 Not Found`.

## 5. Implemented Features

1. Health check and database connectivity.
2. Custom middleware and middleware execution.
3. Request ID generation.
4. Request logging.
5. Request abortion using Gin.
6. JWT-based authentication.
7. Role-based access control (RBAC).
8. Employee CRUD operations.
9. Request validation.
10. Pagination.
11. Filtering by department and name.
12. Sorting by supported fields and order.
13. PostgreSQL database integration.
14. CORS middleware.
15. Panic recovery middleware.
16. Automated tests using Go's `httptest`.

## 6. Run the Project

Start the API from the VS Code terminal:

```powershell
go run .
```

Run these commands to format, compile, and test the project:

gofmt -w .
go build ./...
go test ./...
